# 掩膜模板匹配算法核对

本次核对了以下实现的算法代码：

- [meiqua/shape_based_matching：line2Dup.cpp](https://github.com/meiqua/shape_based_matching/blob/master/line2Dup.cpp)，重点是 `ColorGradientPyramid::extractTemplate`、`quantize`、`pyrDown` 和 `Detector::matchClass`。
- [OpenCV LINEMOD：linemod.cpp](https://github.com/opencv/opencv_contrib/blob/4.x/modules/rgbd/src/linemod.cpp)，重点是梯度方向量化、掩膜筛选、分散特征选择和多层匹配。
- [HALCON create_scaled_shape_model_xld](https://www.mvtec.com/doc/halcon/1811/en/create_scaled_shape_model_xld.html) 与 [set_shape_model_metric](https://www.mvtec.com/doc/halcon/1811/en/set_shape_model_metric.html)。在线站点访问失败后，以本机 HALCON 18.11 随附算子文档核实极性要求。

## 判断

当前“提取图像边缘 → 用掩膜排除不稳定特征 → 建立形状模型 → 在另一张图像搜索”的方向合理。掩膜应该控制模板的有效支持特征，避免被排除内容参与模板评分。无需在运行图片的同一绝对坐标再次涂黑：目标可能已经平移、旋转或缩放。

但当前实现不能称为与 LINEMOD 完全相同。LINEMOD 使用量化梯度方向、方向扩散响应图和离散姿态模板；本项目提取 Canny 亚像素 XLD，掩膜后重建轮廓，调用 HALCON 的缩放形状模型搜索与 least_squares 亚像素精修。HALCON 内部实现并未由这些开源代码证明。

## 掩膜语义差异

OpenCV 原版 `ColorGradientPyramid::extractTemplate` 对对象掩膜腐蚀后做差，偏向选取对象边界特征；meiqua 版本注释掉了做差，使用腐蚀后的掩膜内部筛选候选，并增加局部极大值筛选和分散采样。二者的 mask 都是有效区域，与本项目“红色笔划表示排除”的交互语义相反，需要取相应补集，不能直接照搬对象边界环。

本项目先提取真实图像边缘，再删除被排除的点，避免直接涂黑图像而人为产生掩膜边界。删除点的位置通过 NaN 轮廓分隔符断开，`GenContoursFromFeaturePoints` 分段生成 XLD，避免把被擦除段两端连接成假直线。恢复笔划按先后顺序覆盖排除状态。

采样间距过大时细节会损失，特别是小 Mark 和曲率较大的轮廓。界面现在开放点间距、最大点数、Sigma 和高低阈值，可根据图像调整。这里的高低阈值是 Canny 滞后连接阈值，不等同于 LINEMOD 的弱梯度量化阈值与强候选梯度阈值。

## 本次算法修正

1. `Teach` 在使用已有特征点时仍应用当前 ROI 和掩膜，避免 SDK 修改掩膜后旧特征点直接进入模型。
2. 重建的多边形 XLD 没有 `edge_direction`。先用 `ignore_local_polarity` 创建模型；选择只忽略全局极性时，在设置自定义原点之前，使用 `SetShapeModelMetric` 从模板原图恢复边缘极性。原实现直接指定全局极性，缺少该必要步骤。
3. `MinContrast` 独立支持 1–255，去掉旧图像建模参数 `Contrast` 对它的错误截断。
4. 启用搜索 ROI 但尚未绘制时使用全图搜索；绘制、平移或缩放搜索 ROI 不改变模板数据。

`UsePolarity` 是已有持久化属性名，本次保留其历史映射：true 为忽略局部极性，false 为只忽略全局极性，界面提供对应说明。

## 验证范围

`tests/Run-Regression.ps1` 覆盖当前图直接测试、换图复用模型、不同图片尺寸不修改模板、搜索 ROI 调整后模型字节一致、阈值联动、缓存特征上的掩膜、全局极性建模、手绘 ROI 与移动/缩放、连续笔划与撤销。

合成非对称图形的三组平移/旋转/缩放测试，中心误差约为 0.005、0.287、0.374 px。此结果仅描述回归样例，不能替代实际相机图像上的精度和鲁棒性评估；本次没有进行 LINEMOD 与 HALCON 的同数据集性能竞赛。
